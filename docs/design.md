# Fiber Lens UI 设计方案

> 版本：v0.4 设计稿（待实现） ｜ 状态：已与需求方确认方向
> 本文档是 dsh-fiber-lens 视觉与交互设计的唯一权威来源，实现以此为准。
> v0.3 修订：布局校验、三档阅读深度、动画纪律、虚线按需渲染、快照导出、代码分层——这些不变量源自 archify 图集技能在 12 张架构图交付中验证过的设计原则。
> v0.4 修订：确立双镜头架构（机制镜头 + 会话镜头）。会话镜头只渲染当前会话参与的插件，节点三态 + 在飞操作细化；机制镜头承担 Cordis 原理可视化（fiber 生命周期 / inject 依赖解析 / 服务注册）。不动 Cordis 内核，不提上游 PR。

---

## 1. 设计定位

**"一个活的运行时 X 光片"** —— 双镜头观测器：

- **机制镜头**：让 Cordis 的原理性工作机制（fiber 生命周期、inject 依赖解析、服务注册注销）被实时看见。
- **会话镜头**：让当前会话里哪些插件在干活、正在干什么，被实时看见。

审美对标：Linear 的克制 + VS Code 调试面板的信息密度 + 暗色科技感（继承 cordis-core 架构图集验证过的视觉语言）。

真实数据特性（设计必须服务于它们）：

- 264 个 fiber 节点，树深通常 5-6 层（机制镜头）
- 会话参与集通常 10-30 个插件（会话镜头）
- 秒级差量轮询（ping/version + snapshot）
- version 事件流由 Cordis `internal/status` / `internal/plugin` / `internal/service` 驱动
- 会话参与集由会话日志事件流推导（tool/call、llm/stream、turn/*、step/*）

**时间纪律**：fiber-lens 不保留任何时间线。事件的精确顺序、时间戳、因果链归 Trajectory 视图；fiber-lens 只回答"现在"。

## 2. 双镜头架构

面板头部提供镜头切换：

| 镜头 | 回答的问题 | 节点集合 |
|------|-----------|---------|
| 🔬 机制镜头 | Cordis 是怎么工作的？ | 全量 fiber 树 |
| 💬 会话镜头 | 这个会话里谁在干活？ | 当前会话参与集 |

两个镜头共享同一份快照数据、同一套 DAG 渲染管线（布局/缩放/校验），只是过滤规则与解说层不同。树列表视图保留在机制镜头下（全量观测的紧凑形态）。

## 3. 视觉系统

| 元素 | 方案 |
|------|------|
| 主题 | 跟随 DSH 亮/暗主题（`--dsw-*` token + 回退值），暗色为 slate 深蓝 + 玻璃拟态 backdrop-blur |
| 状态色板 | 六色（与 cordis-core 图集一致）：active `#34d399` / pending `#fbbf24` / loading `#22d3ee` / unloading `#fb923c` / failed `#fb7185` / disposed `#64748b` |
| 参与态 | 会话镜头专用：已参与暗色（40% 不透明度）/ 正在经手高亮（100% + 发光描边） |
| 字体 | JetBrains Mono / ui-monospace；数字 `tabular-nums` 对齐 |
| 状态指示 | CSS 绘制发光圆点（box-shadow 光晕），不用 emoji；状态即色彩 |
| 层级表达 | 缩进 + 左侧 tree guide 引导线，hover 时引导线增亮 |

## 4. 共享 DAG 渲染层

### 4.1 布局算法：分层整齐树（确定性，不用力导向）

关键决策：**手写 tidy tree 布局，不引入 d3-force 等库**。

- 挂载结构本质是树（每 fiber 恰一个 parent），树是 DAG 的特例
- 算法：叶子按名字排序分配槽位，父节点居中于子节点，层级轴 = depth
- O(n)、确定性；新节点插入时局部重排，已有节点位置尽量不动，图不整体抖动
- 服务依赖边作为覆盖层三次贝塞尔曲线画在骨架上

**布局不变量（每次布局结果必须满足）**：

1. 相邻节点最小间隙 ≥ 8px（clear gap，不是中心距）
2. 任何边（实线/虚线）不穿越无关节点
3. 标签不压线、不压节点

**增量校验**：每次 diff 更新后只对变化的子树重跑布局 + 校验；校验失败时回退到上一个合法布局而不是硬画，并向 console 报告违规子树。

布局方向：**自左向右**（root 在最左，depth 向右展开）。

### 4.2 缩放与平移

滚轮缩放（0.2x–3x，围绕光标）、拖拽平移、双击复位（手写 transform，约 60 行，零依赖）。

### 4.3 机制镜头专属：inject 依赖可视化

- pending 节点画"等待中"虚线，指向它缺失的服务名（`missing` 字段）
- 服务出现瞬间：虚线收拢消失，节点 pending→active
- **因果解说**：由 `missing` 数组的 diff 生成——"因为 `sessions` 服务出现，所以激活"；卸载时同理——"因为 `llm` 服务消失，所以卸载"
- 服务注册/注销：服务名标签在 provider 节点上亮起/熄灭

**明确放弃**（Cordis 内核未暴露事件，不动内核、不提 PR）：
- effect 逆序撤销的执行过程
- waterfall 监听器级经手归属

### 4.4 机制镜头规模策略

264 节点全量渲染无压力，不做虚拟化。默认折叠 depth > 2 的子树（`+N` 角标，点击展开）。

## 5. 会话镜头

### 5.1 节点三态模型

| 态 | 视觉 | 含义 |
|----|------|------|
| 未参与 | 不渲染 | 本会话事件流中从未出现 |
| 已参与 | 暗色（40% 不透明度）在图 | 本会话出现过，此刻不在干活 |
| 正在经手 | 高亮（100% + 发光描边） | 此刻处于 call→result 区间内 |

### 5.2 参与集推导（累积态）

- 数据源：当前会话的日志事件流（`tool/call` → 工具插件、`llm/stream` → LLM provider、`turn/*`/`step/*` → agent-loop）
- 推导方式：一次性集合运算，`Set<插件名>`，O(事件数)，不保留时间序
- 工具名 → 插件名的映射：优先读 tools 注册表的 fiber 归属（**实现前必须验证该归属是否存在**）；不存在则退而使用命名约定（`bash` → `tool-bash`）
- 会话切换 → 参与集清空重算；无当前会话 → 空态提示

### 5.3 在飞跟踪（高亮态）

- Host 维护"当前进行中的调用集合"：`tool/call` 进集合、`tool/result` 出集合；`llm/stream` 以 step 区间为界；agent-loop 以 turn 区间为界（常亮是诚实——它是本轮驱动者）
- 只跟踪区间，不记时间戳，不做衰减窗口

### 5.4 节点细化：在飞操作

节点第四态——**展开态**（正在经手 + 点击）：节点变为"正在进行的操作"的窗口。

| 插件类型 | 展开内容 |
|---------|---------|
| 工具插件（tool-*） | 当前调用的参数摘要 + 所在关口（pre/execute/post） |
| LLM provider | 流式状态：已收 chunk 数、当前 step |
| agent-loop | 当前 turn/step 编号 |
| subagent | 被委托的子代理、任务摘要 |

**纪律**：节点内部只显示"正在进行的这一次操作"，绝不显示历史。`result` 回来 → 展开内容消失，节点退回"已参与"暗色。并发调用显示最新一个 + `+N` 角标。

### 5.5 隐形参与者

只走 waterfall 不留会话事件的插件（timeout 守卫、permission 审批等）不参与执行路径的呈现，暂不出现在会话镜头。待 Cordis 暴露 listener 归属后再进图。

### 5.6 fiber-lens 自身

fiber-lens 的数据通路（fetch ping/snapshot）不产生任何会话事件，因此它永远不会出现在会话参与集里——观察者把自己观察出了画面，这是行为决定的，不是排除表。机制镜头（全量观测）里它照常显示。

## 6. 动画系统

**核心纪律**：所有动画必须由数据 diff 触发且有明确结束态；不允许任何常驻循环动画。`prefers-reduced-motion` 时全部回退为静态状态色。

**面板生命周期**
- 打开：`scale(0.92) + fade + translateY(12px)` 弹簧入场（cubic-bezier(0.22,1,0.36,1)，300ms）
- 关闭：反向 150ms 快速退出

**数据驱动动画（全部有限、diff 触发）**
- 状态变化节点：颜色 morph 400ms + 扩散脉冲环
- 新增 fiber / 新参与插件：pop-in（scale 0.6→1 + fade）
- 消失 fiber：灰化淡出 400ms 后移除
- 依赖激活：光点沿服务虚线流动一次（stroke-dashoffset，1s，不循环）
- 进入"正在经手"：描边发光淡入；退出：淡出
- pending 节点：静态琥珀色 + hover 时发光（不做常驻呼吸）

## 7. 运行时快照导出

把当前 DAG 快照导出为静态 PNG/SVG，用于 issue 报告、文档插图、bug 现场分享：

- 导出内容：当前镜头下可见的 DAG 画布（含展开状态与选中高亮）
- 剥离项：hover 态、动画中态、面板 chrome
- 导出即静态：颜色取导出时刻的状态色板，不带动画
- 触发方式：面板工具栏"导出快照"按钮

## 8. 实现约束

**代码分层管道（严格单向，每层只依赖上一层）**：

```
snapshot（轮询：fiber 状态 + 参与集 + 在飞集合）
  → derive（镜头过滤：机制镜头全量 / 会话镜头参与集）
    → diff（纯函数，对比新旧，输出 changeKind 标记）
      → layout（纯函数，tidy tree + 三条布局不变量校验）
        → render（SVG/React，只读布局结果，不做计算）
          → animate（CSS 类切换，由 changeKind 驱动，不涉数据）
```

- diff 为独立纯函数模块；store 只负责持有快照和触发管道
- layout 校验失败时回退到上一个合法布局，并向 console 报告违规子树（不静默硬画）
- 全部动画用 CSS transitions/keyframes + SVG SMIL，零 JS 动画库（保持 bundle ~15KB 量级）
- 折叠状态、镜头选择、选中节点存 panel 本地 state，不进快照、不持久化
- 快照字段无需扩展（uid/name/state/depth/parentUid/inject/missing/provides 已够用）
- Host 保持零硬 inject：会话日志读取走查询式（`ctx.get`），拿不到时参与集为空，观测者照常存活

**Host API**：

- `GET /api/fiber-lens/ping` → `{ version }`（现有）
- `GET /api/fiber-lens/snapshot` → `{ version, at, fibers, services, groups }`（现有）
- `GET /api/fiber-lens/participation?session=<id>` → `{ participants: string[], inflight: InflightEntry[] }`（新增；InflightEntry 含插件名、操作摘要、关口、起始事件引用）

**客户端会话感知**：客户端 inject 会话/对话服务（只读），把当前会话 id 作为查询参数传给 Host。Host 不猜"当前会话"——那是用户的 UI 状态。

## 10. 实现前必须验证

| 项 | 验证内容 | 失败 fallback |
|----|---------|--------------|
| Q7 工具归属 | tools 注册表是否记录工具的注册 fiber | 命名约定映射（`bash` → `tool-bash`） |
| 会话事件读取 | Host 能否查询式读取会话日志事件流 | 参与集为空，会话镜头显示空态 |
| 在飞事件订阅 | Host 能否订阅 tool/call、tool/result 的实时事件 | 高亮态退化为轮询日志尾部 |
